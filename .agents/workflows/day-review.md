# Day Review Workflow

Execute this workflow at the end of each implementation day or after major feature milestones to audit changes against HookRelay's architecture invariants.

## Steps

1. Inspect today's changes:
   ```bash
   git diff main...HEAD  # or git diff @{yesterday}..HEAD / git status
   ```

2. Review the diff strictly against the invariants in `AGENTS.md`:
   - Delivery guarantee is at-least-once (no exactly-once claims).
   - Event + outbox row written in ONE Postgres transaction.
   - Postgres is source of truth; queues carry IDs only, never full payloads.
   - Secrets are never logged; API keys stored hashed; signing secrets encrypted.
   - Outbound HTTP calls enforce timeout, redirect cap, size cap, and pre/post-DNS SSRF validation.
   - Every tenant query includes `tenant_id` (zero cross-tenant reads).
   - No head-of-line blocking between endpoints or tenants.

3. Produce a structured review report covering:
   1. **Violations**: Any departures from architectural invariants.
   2. **Missing Tests**: Any uncovered edge cases, negative paths, or failure modes in vitest.
   3. **Missing Docs**: Required updates to `docs/HLD.md`, `docs/LLD.md`, or new ADRs.
   4. **Security Risks**: Any potential SSRF bypasses, token leaks, timing side-channels, or unhashed secrets.
   5. **Interview Questions**: Exactly 3 deep technical interview questions generated by today's code diff, accompanied by concise model answers demonstrating engineering depth.
